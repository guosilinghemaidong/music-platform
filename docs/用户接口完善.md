# Day 5 代码逐行分析

## 文件 1：app/schemas/user.py（Day 5 新增）

class UserUpdate(BaseModel):
    nickname: str = None
    avatar: str = None

### 逐行解释

| 代码 | 含义 |
|------|------|
| `class UserUpdate(BaseModel):` | 修改个人信息的参数验证 |
| `nickname: str = None` | 可选，不传就不改 |
| `avatar: str = None` | 可选，不传就不改 |

> 💡 **设计思路：** 所有字段都是可选的，前端想改什么就传什么，不传的保持不变。

## 文件 2：app/routers/user.py（Day 5 新增）

### 接口 1：获取当前登录用户信息

@router.get("/me", response_model=UserResponse)
async def get_my_info(current_user: User = Depends(get_current_user)):
    return current_user

### 逐行解释

| 代码 | 含义 |
|------|------|
| `@router.get("/me")` | GET 请求，路径 `/user/me` |
| `response_model=UserResponse` | 返回格式（不含密码） |
| `current_user: User = Depends(get_current_user)` | 自动从 Token 解析出当前用户 |
| `return current_user` | 返回用户信息 |

> 💡 **核心理解：** `Depends(get_current_user)` 一行代码实现"需要登录才能访问"。如果 Token 无效，直接返回 401，不会进到函数里。

### 接口 2：修改个人信息

@router.put("/me", response_model=UserResponse)
async def update_my_info(
    user_data: UserUpdate,
    current_user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_database)
):
    if user_data.nickname is not None:
        current_user.nickname = user_data.nickname
    if user_data.avatar is not None:
        current_user.avatar = user_data.avatar
    await db.flush()
    return current_user

### 逐行解释

| 代码 | 含义 |
|------|------|
| `@router.put("/me")` | PUT 请求（修改操作），路径 `/user/me` |
| `user_data: UserUpdate` | 要修改的字段（可选） |
| `current_user = Depends(get_current_user)` | 当前登录用户 |
| `db = Depends(get_database)` | 数据库会话 |
| `if user_data.nickname is not None:` | 只更新传了的字段 |
| `current_user.nickname = ...` | 直接修改 ORM 对象属性 |
| `await db.flush()` | 刷新到数据库 |
| `return current_user` | 返回更新后的用户信息 |

> 💡 **设计思路：** 不传 `nickname` 就不改 `nickname`，只改传了的字段。

### 接口 3：查看其他用户

@router.get("/{user_id}", response_model=UserResponse)
async def get_user_by_id(user_id: int, db: AsyncSession = Depends(get_database)):
    result = await db.execute(select(User).where(User.id == user_id))
    user = result.scalar_one_or_none()
    if not user:
        raise HTTPException(status_code=404, detail="用户不存在")
    return user

### 逐行解释

| 代码 | 含义 |
|------|------|
| `@router.get("/{user_id}")` | GET 请求，路径 `/user/1`、`/user/2` 等 |
| `user_id: int` | 路径参数，自动转成 int |
| `db = Depends(get_database)` | 数据库会话（不需要登录） |
| `select(User).where(User.id == user_id)` | 按 ID 查询 |
| `status_code=404` | 404 = 资源不存在 |

> 💡 **对比 `/me`：** 这个接口不需要 Token，任何人都能查看。

## Day 5 总结

| 接口 | 方法 | 路径 | 需要登录 | 作用 |
|------|------|------|---------|------|
| 获取自己 | GET | `/user/me` | ✅ | 获取当前用户信息 |
| 修改自己 | PUT | `/user/me` | ✅ | 修改昵称/头像 |
| 查看他人 | GET | `/user/{id}` | ❌ | 查看其他用户 |

**Day 5 的本质：** 用 `Depends(get_current_user)` 实现权限控制，完善用户模块的增删改查。
