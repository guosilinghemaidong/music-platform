## 音乐社交平台 — 项目开发文档

本文档整理自 FastAPI + Vue3 音乐社交平台项目的完整代码结构，涵盖每个文件夹和文件的作用、技术栈说明、功能清单，以及 Redis / Docker / 云部署的学习建议。

---

## 一、技术栈总览

**后端**：FastAPI（异步 Web 框架）+ SQLAlchemy 2.0（异步 ORM，驱动 aiomysql）+ Pydantic v2（数据校验）+ python-jose（JWT 令牌）+ passlib（密码加密）+ redis（异步缓存）

**前端**：Vue 3（Composition API + `<script setup>`）+ Element Plus（UI 组件库，全局导入）+ Axios（HTTP 请求）+ Vue Router（路由）+ Pinia（全局状态管理，用于播放器）+ Vite（构建工具）

**数据库**：MySQL 8.0（主数据存储）+ Redis 7（接口缓存，60 秒 TTL）

**部署**：Docker + docker-compose（4 个容器：MySQL、Redis、后端、前端 Nginx）

## 三、功能清单

### 用户端功能

**账号系统**：注册、登录（JWT 令牌）、个人信息修改、密码修改、头像上传

**发现音乐**：浏览全部上架音乐、按关键词搜索、按分类筛选、查看歌曲详情、在线播放、查看歌词

**音乐互动**：收藏/取消收藏歌曲、点赞音乐、发表评论/删除评论、播放次数实时递增

**动态广场**：发布动态（文字 + 多图 + 关联歌曲）、点赞/取消点赞、评论/删除评论、关注其他用户

**关注系统**：关注/取消关注、查看关注列表、查看粉丝列表、互相关注状态显示

**全局播放器**：底部固定播放条、播放/暂停/上一首/下一首、进度拖拽、音量调节、歌词弹窗、自动播放下一首

### 管理端功能

**用户管理**：查看所有用户、启用/禁用账号、编辑用户信息

**内容管理**：添加歌手/专辑/分类（含图片上传）、添加音乐（上传音频+封面+歌词）

**审核系统**：音乐审核（通过→上架 / 拒绝→下架）、动态审核（通过/拒绝/删除）

## 四、核心设计要点

### 4.1 两套数据库会话模式

项目中有两种 `get_db` 写法：

- `get_database()`（定义在 `routers/user.py`）：自动 commit + flush，适合简单 CRUD
- `get_db()`（定义在 `database.py`）：需要显式 `await db.commit()`，适合复杂事务

两者都使用异步 SQLAlchemy，区别在于事务提交方式。

### 4.2 Redis 缓存策略

音乐列表接口 `/music/list` 使用 Redis 缓存，TTL 60 秒。缓存 key 格式为 `music:list:{参数hash}`。当播放次数递增或数据变更时，主动清除相关缓存 key：

```python
cache_keys = redis_client.keys("music:list:*")
if cache_keys:
    redis_client.delete(*cache_keys)
```

### 4.3 音乐/动态生命周期

管理员添加音乐 → status=0（待审核）→ 审核通过 → status=1（上架）。用户端只查询 status=1 的音乐。下架同样设为 status=0。收藏页保留已下架歌曲但禁止播放。

动态类似：用户发布 → status=0 → 管理员审核通过 → status=1。

### 4.4 前端 API 地址适配

开发环境通过 Vite 的 `.env.development` 设置 `VITE_API_BASE_URL=http://localhost:8000` 直连后端；Docker 环境通过 `.env.production` 设为空值，请求走 Nginx 反向代理。Vite 开发服务器也配置了 proxy，代理 14 个 API 前缀到后端。

### 4.5 关注字段语义

`is_followed_back` 字段的含义是"对方是否回关了我"，不是"我是否关注了对方"。前端根据 Tab 上下文判断：关注列表默认已关注（用 `_following` 字段跟踪），粉丝列表才看 `is_followed_back`。

## 五、Redis 和 Docker 学习建议

### 5.1 结合本项目需要学的 Redis 知识

**基础概念**（先搞懂这些）：

Redis 是一个内存数据库，数据存在内存里所以读写极快。它支持五种基本数据类型：字符串（String）、哈希（Hash）、列表（List）、集合（Set）、有序集合（ZSet）。本项目主要用的是字符串类型（存 JSON 缓存）。

**本项目用到的 Redis 操作**：

- `SET key value EX 60` — 存缓存，60 秒后自动过期
- `GET key` — 读缓存
- `DEL key` — 删缓存
- `KEYS pattern` — 按模式匹配查找 key（生产环境建议用 SCAN 代替）

**需要理解的概念**：

- TTL（Time To Live）：缓存存活时间，本项目设 60 秒
- 缓存穿透/雪崩：大量缓存同时过期会导致数据库压力骤增，解决办法是 TTL 加随机偏移
- 缓存失效策略：数据变更后必须主动清除缓存，否则用户看到旧数据（本项目播放次数递增就遇到了这个问题）

**学习资源**：

- Redis 官方教程：https://redis.io/docs/get-started/
- 《Redis 设计与实现》（黄健宏）— 免费电子书，讲透 Redis 内部原理
- 菜鸟教程 Redis 部分：https://www.runoob.com/redis/ — 适合快速上手命令

### 5.2 结合本项目需要学的 Docker 知识

**基础概念**：

镜像（Image）是打包好的应用 + 运行环境，相当于"安装光盘"。容器（Container）是镜像运行起来的实例，相当于"装好软件在跑的电脑"。Dockerfile 是写"怎么打包"的说明书。docker-compose 是"一次启动多个容器"的编排工具。

**本项目用到的 Docker 概念**：

- Dockerfile：定义怎么构建镜像（后端用 Python 3.11-slim，前端用多阶段构建）
- docker-compose.yml：定义 4 个服务（MySQL、Redis、后端、前端）的关系和配置
- 多阶段构建：前端先用 Node 编译 Vue 代码产出静态文件，再把静态文件交给 Nginx 托管，镜像从 1GB 缩到 30MB
- Volume（数据卷）：MySQL 和 Redis 的数据持久化，容器删了数据不丢
- 网络：容器之间通过服务名（如 `backend`、`db`、`redis`）互相访问

**需要理解的概念**：

- COPY 路径是相对于 `docker build` 执行目录的，不是 Dockerfile 所在目录
- `depends_on` 只保证启动顺序，不保证服务就绪（MySQL 可能还在初始化）
- 环境变量传递：`docker-compose.yml` 里的 `environment` 注入到容器，`config.py` 用 `os.getenv()` 读取
- Nginx 反向代理：前端请求不直接到后端，而是 Nginx 转发（`proxy_pass`）

**学习资源**：

- Docker 官方入门：https://docs.docker.com/get-started/
- 《Docker — 从入门到实践》（yeasy）— 中文免费电子书，GitHub 上搜 docker-practice
- 阮一峰 Docker 入门：https://www.ruanyifeng.com/blog/2018/02/docker-tutorial.html
- 多阶段构建详解：https://docs.docker.com/build/building/multi-stage/

### 5.3 建议的学习路径

第一步：先在本项目上实验。`docker-compose up --build` 跑起来后，试着改一行代码重新构建，观察哪个步骤变慢（理解缓存层）。

第二步：学 Redis 命令。安装 Redis Desktop Manager 或 Another Redis Desktop Manager（可视化工具），连接本项目 Redis，观察缓存 key 的生成和过期。

第三步：学 Docker 调试。`docker logs backend` 看后端日志，`docker exec -it backend bash` 进入容器内部执行命令，`docker ps` 查看容器状态。

第四步：尝试自己写 Dockerfile。找一个简单项目（比如纯 Python Flask），从零写 Dockerfile 和 docker-compose，不用 AI 辅助。

## 六、云服务器部署建议

### 6.1 是否推荐？

对于学习和个人项目，非常推荐。成本不高，而且能让你体验完整的"开发→部署→上线"流程，简历上也能写。

### 6.2 推荐方案

**入门方案（最省钱）**：

阿里云/腾讯云的学生机或轻量应用服务器，2 核 2G 内存，一年大约 50-100 元（新用户优惠）。足够跑本项目全部 4 个容器。

推荐操作系统选 Ubuntu 22.04 或 Debian 12，装好 Docker + docker-compose 后，把项目代码传上去，`docker-compose up -d` 就能跑。

**具体步骤**：

1. 买服务器 → 开放 80 端口（安全组设置）
2. 安装 Docker + Docker Compose
3. `git clone` 项目代码到服务器
4. 在 MySQL 容器里手动建表（本项目没有自动建表）
5. `docker-compose up -d --build`
6. 访问 `http://你的服务器IP` 即可

**进阶方案**：

如果想绑定域名 + HTTPS，可以加一层 Cloudflare（免费 CDN + SSL 证书），或者用 Let's Encrypt 免费证书配合 Nginx。

### 6.3 注意事项

- 2G 内存跑 4 个容器会比较紧，如果卡可以关掉 Redis（本项目没 Redis 也能跑，只是列表接口慢一点）
- MySQL 容器默认占约 500MB 内存，可以通过 `command: --innodb-buffer-pool-size=128M` 降低
- 服务器上要修改 `config.py` 里的 `SECRET_KEY`，不要用默认值
- 数据持久化靠 Volume，`docker-compose down` 不会丢数据，但 `docker-compose down -v` 会删数据（小心）

### 6.4 更便宜的替代方案

如果不想花钱买服务器，也可以用这些免费/超低价方案：

- **Vercel + Railway**：前端部署到 Vercel（免费），后端部署到 Railway（免费额度 5 美元/月）
- **GitHub Pages + Render**：前端静态化后放 GitHub Pages，后端放 Render（免费套餐）
- **Oracle Cloud 永久免费层**：4 核 24G 内存的 ARM 实例永久免费（需要抢，经常没库存）

不过对于学习 Docker 来说，还是建议买一台便宜的云服务器，完整走一遍部署流程。
